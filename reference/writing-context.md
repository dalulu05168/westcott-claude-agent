# 按任务读取与续写

| 需求 | 本轮读取 |
| --- | --- |
| 润色一句或只改指定条目 | 用户给的原句、必要相邻条目、用户点明的格式。已有足够原文时直接改。涉及编号归属才传 `member_ids` 查询相关成员。 |
| 续同一场、补条数或收尾 | 一份本场断点，及其指定的正式稿末段。取得相同修订和确认正文后复用。内容变更时只刷新受影响段落。 |
| 完整晚课或完整多人场 | 当前课题、待办任务、上一课相关结尾、指定人员和证据。先定本场切入和停点，再交给编剧。收稿后由独立审稿核内容、任务线和证据边界。 |
| 最新市场、开盘或新闻 | 只把本轮相关日期、市场、盘口及核过的关键事实交给编剧。原报告和实际核查来源由导演留存。 |

## 局部修改

单句由总导演直接改，保留本轮确认的原意、数字、标点要求和指定术语。选中多条中的某几条或涉及价格、时间、百分比时，调 `validate_local_edit`。传入同一段原文及核对用成稿，二者都带必要的未修改相邻条目。用 `editable_blocks` 填这段原文中的相对序号。用户明确要求改数字时才用 `allow_number_changes: true`。可用 `protected_literals` 保留股票代码、用词或链接。检查后只交用户要改的正文。

## 续写与人物

场内先读 `get_scene_checkpoint` 的默认末段，用 `last_spoken_line` 接最后一句台词。上一课只需结尾时用 `read_record` 的 `view: tail`，需要前面证据时按 ID 读全文。已有足够最新原文时直接复用。正式稿修订改变时，读取确认正文，按 [场内断点](operations.md#场内断点) 替换。跨场事项只把本轮相关的已发提醒、未答问题或活动状态传给编剧。

用户在 Google Docs 更新当天稿时，先核指定日期页签最新修订、末段和已有条数。以已确认正文为续写起点，原有编号、用户新增的【持仓】占位和修改保留原样。补条数或插入时只交新增条目，并标明插入位置。续同场时顺接现有停点，开群和已发题面沿用原文。指定日期页签为空时，只在用户允许并能定位到汇总页签时核对汇总中的最新正文。

已知出场编号时，用 `get_cast_context` 的 `detail: focused` 带 `member_ids`。选人前需要看候选时才用 `detail: selection`，它只读所需身份和分组。再查选中成员的声线、成长和近期问题。聚焦结果的 `omitted_questions` 表示尚有其他记录，仅在本场要回收旧问题时查询 `detail: full`。审稿员通常只需正文、直接前文和当前任务的证据边界。

## 压缩 Claude Code 对话

完成用户明确授权保存的工作后先读回断点。需要收短当前聊天时，可以在 Claude Code 输入。

```text
/compact 保留本场布加勒斯特日期、场次、已采用和已发的断点版本、末句原文、累计条数、等待节点和未答问题。保留当前潮汐蓝图任务、下一课边界和场内人物。恢复后先读取场次断点，按用户当前要求继续。
```

压缩后的摘要用于定位项目状态。正式正文、是否发布、是否完成和后续课题以核对过的本地记录和当前用户指示为准。需要比较会话占用时，在相同模型和原稿条件下，用 Claude Code 的 `/context` 记录压缩前后；订阅额度另看账号实际用量。[Claude Code 命令](https://code.claude.com/docs/en/commands)
