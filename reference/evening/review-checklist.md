# 晚课验收清单（审稿用）

来源：旧版 `westcott-efficient-workflow` 2.3.2 的晚间 `review.md`、`part-08.md`、`part-09.md` 及 `contracts.md` 中不依赖脚本的检查项，2026-11-19 并入。机器能查的格式、口吻和条数交给 `validate_speech_format`、`validate_whatsapp_voice`、`validate_scene_count`；本清单查机器查不了的部分。与 [CLAUDE.md](../../CLAUDE.md) 冲突时以 CLAUDE.md 为准。

## 怎么审

1. 先确认待审稿件、用户范围和课程状态。没有采用或授课依据的候选稿不当作已发生的历史。
2. 每项给「通过／待核／不通过」，指向具体原句、段落、图号或文件。没有证据不默认通过。
3. 只修有证据的问题和受它影响的地方，不借审稿重排全部逻辑；复查只看上次指出的问题和改动带来的新问题。
4. 结构检查通过不等于事实、自然度和图文都通过。

## 必过项

| 类别 | 检查 |
| --- | --- |
| 课程逻辑 | 按 [课程路线](course-route.md) 从低到高、符合当前阶段、与前后课衔接；四阶段不等于四周，没有理解证据的推进记待核。 |
| 技术／理念呼应 | 理念课回应最近一两节技术课的误区，不另起炉灶。 |
| 授课逻辑 | 按 [授课方法](teaching-method.md)：先回顾白天市场、有真实问题引导、再进教学图、三类例子齐、有总结与承接（一个原则、一个误区、下一课问题）。 |
| 理念推进 | 自然、渐进、一课一点，没有一次说太多；没有硬营销、收益保证、无依据的身份能力陈述或虚构背书。 |
| 表达边界 | 事实、解释、待验证条件分开；市场数据有时点和来源；可以提机构行为的可能，但没有把机构身份、意图或一级市场传导写成定论。只加「可能」却没有任何线索也要改。 |
| 成员互动 | 按 [课堂互动](interaction.md)：作用不重复、误解合理且被纠正、有人较真；没有集体夸奖、替机构作证或全员模板化；不要求所有人都发言。模拟反馈不计入真实学习结果，模拟说明在代码块外。 |
| 白天承接 | 晚课翻出的白天原话在当天上午或下午稿里真的出现过；David 先接住那句话里的一个细节再讲当课观点。 |
| 周二、四 | 没有显式或变相的课后任务（明日交图、提交观察、打卡）；课堂即时辨析可以保留。 |
| 课件 | 按 [课件规范](../courseware.md) 核实际文件：像素尺寸、绿涨红跌、K 线与量柱关系、图号连续、Logo 比例与遮挡、文字可读。没有文件或无法渲染时写待核。 |

## 典型不通过

- 直接跳到复杂形态，或理念课与技术课毫无关系。
- 先生一出场就硬讲机构身份；把机构行为当作既定事实。
- 成员集体夸赞先生，明显不自然。
- 图表风格混乱、Logo 失真或遮挡主体。
- 周二、四仍安排作业。
- 理念课只讲空话，没有钩子和方向感。

## 交付

每项写成「项目—通过／待核／不通过—原句或图号证据—最小修改」，最后给「通过」或「需修改」的总结论和未解决项。不替总导演登记采用、写计划或发消息。
