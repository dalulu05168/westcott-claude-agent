# 晚课课程路线与排课（总导演用）

来源：旧版 `westcott-efficient-workflow` 2.3.2 的晚间 `control.md`、`part-01.md`、`part-03.md`、`part-06.md`、`part-07.md`、`progress.md`，2026-11-19 并入。与 [CLAUDE.md](../../CLAUDE.md) 冲突时以 CLAUDE.md 为准。授课写法归编剧，见 [授课方法](teaching-method.md)。

总纲：在固定晚间时段，围绕技术形态课和理念课，从易到难、从结构到判断、从图形到市场、从理解到信任，组织先生授课、成员互动、标准课件和长期理念递进。

## 先判断本次范围

排课、单课规划、整课制作、局部编辑、恢复进度，只做用户本次要的那一种。只要求排课时不写整堂对话、不出图。每堂课定一个核心知识点、一项关键判断能力、一个要纠正的误区；辅助概念服务主线，不因案例丰富扩成多堂课。成员「理解了」要有课堂提问或复述等依据，没有反馈记为待观察。

## 四阶段路线

形态顺序保持不变。四周是可用的排课窗口，不是必须四周讲完；四阶段不等于四周。需要复习或调整时，记下原因、受影响课次和下一步承接，不悄悄跳过基础。

| 阶段 | 目标 | 技术课重点 | 理念重点 | 进入下一阶段前应能做到 |
| --- | --- | --- | --- | --- |
| 一、形态基础建立期 | 形态有形成过程，不是看到轮廓就能下结论 | 趋势放缓与整理、矩形/箱体、支撑阻力与区间边界、突破与确认、失效与重新观察 | 不急于下结论；证据不够时等待是能力；「看见了」不等于「看懂了」 | 指出区间边界，区分形成中、待确认、失效 |
| 二、基础反转形态期 | 认识经典底部与顶部形态 | V 形反转、双重底、双重顶、三重底/顶、头肩底/顶（中段后） | 反弹不等于反转；急跌急涨最容易误导；证据链比主观愿望重要 | 区分反弹与反转，说明颈线、确认与失效的作用 |
| 三、持续整理与延续形态期 | 不是所有形态都意味着反转 | 上升/下降三角形、对称三角形、旗形、楔形、平台整理 | 市场常常不马上给答案；延续也要验证；机会质量比数量重要 | 结合前趋势说明延续假设，并提出反向情景 |
| 四、综合判断与高级理解期 | 比较多个形态，形成完整分析框架 | 假突破、多形态比较、同图多情景、形态与量价、形态与市场环境 | 判断是管理概率不是猜输赢；不修正才危险；纪律比猜对重要 | 列出事实、候选情景、确认条件和修正条件 |

尚未掌握时退回本阶段对比图（箱体图比较触及与有效确认、相似轮廓比较成功/未确认/失败等）。这是理解检查，不是收益考核；单次答对不等于稳定掌握。

## 每周结构

- **周一、三、五技术课**：从低到高推进，不跳级；课后练习按用户材料决定。
- **周二、四理念课**：必须呼应最近一两节技术课，不另起无关主题，不布置作业，也不以「观察任务」「打卡」「次日提交」变相布置。
- 周内衔接：周一接上一课未解决的问题；周二拆解周一误区；周三推进相邻知识；周四呼应周三并可串联周一；周五讲新知识或综合比较。
- 节假日、停课或延期时沿用未完成进度，不为赶星期合并过多知识点。周末未明确安排时不自行补课。主课 20:00，时区按 Europe/Bucharest。

## 技术课与理念课对应（建议）

| 技术课 | 理念课主题 |
| --- | --- |
| 矩形整理 / 箱体 | 看到区间，不等于知道方向 |
| 突破与确认 | 等待确认不是犹豫，而是纪律 |
| V 形反转 | 快速波动最容易诱发冲动判断 |
| 双重底 | 反弹为什么会让人误以为已经见底 |
| 双重顶 | 高位为什么更容易忽略风险信号 |
| 三重底 / 三重顶 | 新证据出现后如何修正原判断 |
| 头肩形态 | 结构思维为什么比单点预测可靠 |
| 三角形 | 看懂结构比猜方向更重要 |
| 旗形 / 楔形 | 延续中的机会与陷阱怎么区分 |
| 假突破 | 执行规则为什么比情绪重要 |
| 综合判断 | 建立自己的观察框架 |

## 理念植入节奏

| 阶段 | 可推进的理念 |
| --- | --- |
| 初期 | 专业分析、结构观察、确认过程 |
| 中前期 | 不同市场参与者视角、大资金行为的可能性 |
| 中期 | 一级市场 / 二级市场基础概念 |
| 中后期 | 机构视角、交易结构、流动性 |
| 后期 | 自然引出「我们的方法」「我们的分析框架」 |

每课只推进一点，具体写法见 [授课方法](teaching-method.md#理念递进)。

## 单课方案（派给编剧前定好）

每堂课交给编剧和课件前，总导演在内部定好：

1. **课程方案**：主题、所属阶段、技术/理念类型、教学目标、与前后课的承接、本课理念推进点和暂不展开的内容。
2. **授课逻辑**：怎么开场、回顾白天哪个现象、案例用不用（采用/不采用及原因、来源与截止时点）、进哪张教学图、怎么总结承接。
3. **互动设计**：要用到哪几种作用、谁提误区、谁追问、谁接回白天原话。
4. **图表要求**：需要哪些图、图号与作用，交课件 Agent。
5. **验收要点**：是否跳级、是否呼应、是否自然、有没有过度宣传、有没有把可能说成事实，交审稿 Agent。

图表和授课沿用同一主题和术语，不各自改写判断条件。缺市场数据时照样完成模拟教学部分；缺正式 Logo 时只能交版式方案，不称品牌成品已验收。

## 进度登记

旧版的 JSON 检查点改用本项目的状态工具：计划用 `save_agenda`，整课完成用 `complete_lesson`，采用稿用 `record_adoption`，场内停点用 `save_scene_checkpoint`。状态分「计划、草稿、已采用、已授课」，草稿不代表已授课；没有实际课堂反馈时，不把预设互动写进成员学习结果。每课记录至少能查到：课次、日期、类型、已讲知识、理念推进点、反馈依据、待解释问题、下一课位置。状态冲突先列差异，不按文件日期猜。

## 不归晚课管的

上午、下午资讯，发群，自动推送，买卖记录，新闻配图加工，都不在本路线里，按 [运营规则](../operations.md) 和 [新闻规则](../news-broadcast-policy.md) 处理。
