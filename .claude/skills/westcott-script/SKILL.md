# 课堂写作（写作主干沿用旧版 westcott-efficient-workflow 2.3.2）

一句话：写出罗马尼亚人在 WhatsApp 股票群里真实聊天的样子。短、随意、直来直去，有人抢话、有人较真、有人只回一个表情。不讲课、不写报告、不排队。

## 动笔前（导演先定戏，不输出给用户）

1. 用用户本次范围和最后有效正文，定好起点、顺序、条数、停点。只要片段就不套整场配额。条数按每 6 分钟一条（每小时约 10 条）先算好：整场上午约 30、下午约 35、晚间约 30 条（±2），停点和节选按实际起止时刻算；给锚点后的播报、推票和收尾留位置。
2. 定这一场的几个点：
   - **钩子**：当天最重要的市场事件，或前一场留下的话题。用它开场或串场，不照搬前一天的开场套路。
   - **冲突和追问**：至少一处成员之间有不同看法、互相纠正或追问（如「坏账是收不回来，这个是还没收回来吧？」），不是一排人各说各的。
   - **人物线**：挑一两位成员前后呼应。新成员前面提问、后面自己说懂了一半；有人一直不服气，留到下一场。
   - **节奏**：成员回应的人数和位置每段不同。
3. 状态和素材：用 `mcp__westcott-state__*` 查本场断点（`get_scene_checkpoint`）、跨场交接（`get_handoff`）、成员近况（`get_cast_context`），用户要求时用 `save_draft` 存草稿。Google Docs 读不到（未授权、缺凭证、连接失败）时**不停下**，用用户给的材料和已保存的状态直接写，在代码块外一句话说明缺了哪段。
4. 只读本场用到的编号。名册、称呼、出场人数见 [成员口吻与出场](../../../reference/member-cast.md)；口吻范文见 [金牌样稿库](../../../reference/gold-samples.md)。

## 场景不走固定循环（用户 2026-11-17 要求）

不写成「助理发一条新闻 → 四五个成员围着这条聊 → 助理再发下一条」。按真实群聊随机穿插：

- 新闻发出前，成员自己先提起一件事（问某只票、BET、汇率、昨天的推票），助理的新闻正好接上，或者跟它无关；
- 新一条新闻发出后，还有人在接着聊上一条，或回头答之前别人问的问题；
- 有的新闻只有一两个人回应，有的引出一段沾边的闲聊（存款、国债、分红、午饭、天气），话题漂一下再回来；
- 两三个人之间来回接话，同一个人隔一会儿再冒出来；有人只回一个表情或一个词；
- 助理偶尔简短回应成员的问题，不是每次只发新闻。

不必每场都用上，也不轮流套用。写完按「助理／成员」顺序看一遍：每条新闻后面都是人数差不多、只谈这条新闻的一组成员，就是在循环，要重排。一场里几乎每个编号只出现一次，就是排队，也要改。

## 成员怎么说话

- **默认一句短话。** 「我去看看」「那我选A」「还没看，今天消息太多了」「期货归期货，正式开盘再看看」。不设字数，真实群里多数一两句；有人连发两三条，有人偶尔认真写一长段问题，有人只回一个表情。按「这个罗马尼亚人此刻在群里会怎么发」来定，不为整齐把每个人写成同一长度、同一表情密度。
- **成员之间不讲课。** 有人问「这个SMT是什么？」，回一句「也是BVB的交易市场，规则跟主板不太一样」就够。每条资讯后最多一位成员多说两句。
- **追问实际的事，少做分析式点评。** 「BET今天怎么样？」「股价今天怎么样？」「家得宝财报出来了吗？」
- **直接、较真、爱比较。** 质疑和反问明显多于附和；爱拿定存、TEZAUR／FIDELIS 国债、派息、汇率来比：「那SNP派息到底算不算赚？」「国债利息摆在那儿，还折腾股票干嘛🤷」。只说比较和疑问，不编个人持仓或收益。
- **有立场。** 信服、质疑、反驳、自嘲都可以；反驳是在表达观点，不是捣乱。空表态（「回去试试」「谢谢先生」）和学习群表态（「这个懂」「记下了」「学到了」）一场最多一两句。
- **一读就懂。** 提到个股或板块点名代码或指数（「RRC连跌两天了，现在进是不是太早？」）。
- **表情按人。** 有人常带一个（😅🤔🙂😄🤷👍），有人从来不用。不用 🔥🚀💰。
- **判断题、竞猜。** 只给选项加半句理由或不给（「B，哪有什么一定的」「我也选A，猜一个😄」），不让任何人说得像知道答案；后面也不让人点破「这不就是刚才那道题吗」。
- **不知道后台。** 不说「开了没」「数据还得等一会儿」「等核对完」。
- **颜色。** 绿涨红跌；涨说「收绿／见绿」，跌说「飘红／红了」，未收盘不说「收绿」。
- **称呼。** 叫「David先生」，不叫「老师」「大师」；@ 人用名字，不用编号。
- **全部用简体中文。** 不夹 Păi、Mda、Gata 等罗马尼亚语词；不用中国成语典故、网络梗、国内股民黑话（上车、抄底、割肉、洗盘、庄家、追高、韭菜、稳了……）和中国生活背景（微信、红包、春节、人民币、A股）。
- **持仓。** 「已买／持仓」由用户在文档里加【持仓】占位；我们写成不带个人事实的问法（「要是手里有SNP，这种时候该看什么？」）。

用户认可的口吻对照表（「不像罗马尼亚群的写法 → 可以怎么写」）在 [金牌样稿库](../../../reference/gold-samples.md) 的 G01 一节，先看它再动笔。晚课里成员插话的六种作用、设计边界和交稿前语义检查见 [课堂互动](../../../reference/evening/interaction.md)。

## 资讯助理

- 开群首句固定「🌤 大家早上好！欢迎回到 ELLERY WESTCOTT 社群！」，按时段换「早上／下午／晚上」。
- 像群里的资讯助理说话，直接说，不加自造的小标题，不写「经核实」「核查显示」「数据截至」。称呼「大家／各位／成员」。
- 新闻：`🇷🇴 罗马尼亚财经新闻｜短主题` 或 `🇺🇸 美国财经新闻｜短主题`；第二段只写核心事实和关键数字（「约／附近」即可），用「据今日公布的财报」「根据BVB今日公告」这类自然引述；第三段一两句点出对罗马尼亚市场或相关代码的影响，以「接下来，我们重点关注……」收尾。下方一行「配图：」加图片直链。范文见 [助理与先生发言规范](../../../reference/speech-format.md#资讯助理的财经新闻)。
- 活动：只写题目、回答方式和交给顾问 Gabriela，不写积分、不公布答案；提醒轻松、每天换说法。
- 闭群三句：感谢参与 → 下一场关注什么、欢迎回来 → 祝福再见。措辞每天换，不罗列刚聊过的事。

## David 先生

写晚课前先读 [授课方法](../../../reference/evening/teaching-method.md)：技术课九步、理念课五步、可能性表达、教学图与实际案例分开、理念递进。下面是要点。

- 只在晚间授课和周日复盘出现；**上午、下午 0 条**。
- 每次两段：先回应眼前的疑问，再讲道理和怎么验证。用专业术语（支撑、阻力、突破确认、回撤、成交量、估值、股息率），不用股民口头说法。
- 可以先抛问题让成员猜，再揭晓下一张图；连讲两三段后让成员集中回应，不机械交替。
- 晚课成员翻出白天原话来问时，先接住那句话里的一个细节，再讲当课观点。「跟着先生学」靠一次次讲清判断步骤建立，不自夸、不安排集体夸他。

## 三场默认

- **上午**：约 30 条（09:00–12:00）。保留自然问候、顺口附和、散户对眼前消息的反应；在图、资讯或案例的关键位置，让少数成员点出一个具体疑问或误区，上午留着答案。内部标【下午接力】或【晚课切入】，台词里只留自然发言。
- **下午**：约 35 条（14:00–17:30），David 0 条。优先接上午留下的问题。下午可以写看得见的现象和开放问题，但任何角色都不提前说出晚课结论、不用反问预设答案、不代 David 总结。周一三五先把 3 条资讯发齐，最后一条到推票节点之间、推票之后都给成员留够发言；周二四 14:00 判断题，新闻按发布时间推进。
- **晚间**：约 30 条（19:30–22:30）。19:30 助理引导课前探讨（不剧透），20:00 David 授课；信随组或细节型成员把白天原话翻出来接给先生。周二四不布置作业。

## 编辑和续写

- 只改指定范围：「只改第二条」只交第二条；「已有21条补到35条」新增14条，所有角色计入，已有条数从正文核对。
- 保留原意、立场、不确定性、数字、币种、代码、条件和顺序。原句自然就不改；不为修辞新增事实；发现数字矛盾单独指出。
- 停点后不闭群、不加作业或新课程。
- 自检一次：这句是否保留原意、增加有效信息、超出证据或重复？只有具体缺陷才改，最多两轮，不多轮全文重写。

| 输入/要求 | 合适处理 | 不应处理 |
|---|---|---|
| 「只改第二条」 | 只交付第二条，保留数字、条件和立场 | 顺便重写第一条或补结尾 |
| 「如果昨日80万股，今日120万股，增幅应该是50%，对吗？」 | 「昨天80万股，今天120万股，那成交量就是多了50%，对吧？」 | 写成「股价涨了50%」或删去疑问 |
| 「我可能明天再看。」 | 「我也许明天再看看。」 | 「我明天会买。」 |
| 「等待开盘，不闭群」 | 写到未知数据前停下 | 加「我们晚上见」或编开盘结果 |
| 两位成员对同一概念有疑问 | 一位问比较基准，一位确认适用条件 | 人人复述同一结论 |

## 交付前检查

1. 意义：立场、条件、不确定性、时间与比较对象变了吗？
2. 范围：交的是指定部分吗？有没有多加课程、行动或结尾？
3. 连续性：人物能否知道尚未公布的信息？前一场草稿不当作群里发生过的事。
4. 口吻：把整场连读一遍——相邻两条是否只换词重复？是否在循环、在排队？有没有讲课腔、报告腔？
5. 事实：模拟、引用、推断和实际记录分开；数字按本场证据写。

再跑 `validate_speech_format`（`strict_layout: true`）、`validate_whatsapp_voice` 和 `validate_scene_count`。工具通过只说明机器能查的项目通过，口吻是否自然仍要自己读。

## 最终交付排版

在聊天中用一个 Markdown 纯文本代码块包裹本次完整剧本。开围栏由三个反引号紧接 `text` 组成，闭围栏用三个反引号，各自独占一行。整场、节选和单条台词都用这一格式。块内第一行直接写首位角色，不加开头标签、标题或说明。教学模拟说明、交接和审稿结论放块外。

每个角色标记独占一行，如「29男：」或「===== 资讯助理 =====」。正文从紧接的下一行开始。发言之间直接换行，禁止空行。新闻或讲解同一条正文按规定分段，段内需要分隔时保留空行。严禁角色标记与正文同行或多人发言拼在一行。格式校验传块内纯文本和 `strict_layout: true`，保留原始换行。
